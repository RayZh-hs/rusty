## 从 RV32 到 RV64
### 写在前面
Q：我 RV32 写的好好的为什么需要切到 RV64？
A：今年我们希望将整个评测后端从 Reimu 模拟器迁移到真实的 RISC-V 硬件上，这样评测速度会快非常多，且测试结果也更加贴合真实的表现。

但目前市面上仅有 RV64 的机器(~~孩子们CCF的32位老爷机都退役5年了~~)，而 RISC-V 又没有像 x86 一样的低位兼容，因此我们只好做一个艰难的决定，让各位将 target asm 迁移到 RV64 上。

Q：迁移到 RV64 的 Workload 大吗？
A：根据助教的估算，如果你的 asm 没有乱到自己认不出来的话，预计至多只需要2-3h. 这也是这篇文章存在的意义：帮助大家节省修改的时间。

助教时间有限，因此本篇 Tutorial 可能不完整，欢迎各位的指正。如果有指正我们会在给分上考虑酌情加分。

### 数据保证
我们保证所有 Codegen/优化的测试点里：
- 整数的加减乘除结果都在32位整数存储范围内，不会超出范围。
    - 注：此处的不会溢出前提是你的 asm 是正确的。由于 codegen 爆炸导致的溢出不在此列。
- 如果你认为某个测试点不符合要求，可以联系助教。只要质疑合理，我们会将其删掉或做相应改动。

### 修改指北
整体而言，需要对源码做的调整是非常小的。在给定前面的保证后，从 RV32 到 RV64 绝大部分的指令都可以复用。下面我们会给需要调整内容的一个 outline:

#### 关于运算符
在 RV64 里，理论上32位的运算指令形如`addw`, `subw`, ... 即对许多运算指令添加了一个 `w` (word).

具体添加了 `w` 的指令如下：
```
addw/addiw/subw
sllw/srlw/sraw
slliw/srliw/sraiw
mulw/divw/divuw/remw/remuw
```

由于 RV64 对 32 位整数储存有比较严格的规则（高32位必须是第32位的重复），所以我们依然建议各位把所有整数运算的指令设置成带 `w` 的形式。

如果一条指令没有对应的带 `w` 形式，你不需要额外处理它，它自然是可以工作的。（比如比较运算或位运算）

（**注意指针运算不要改！指针运算不要改！指针运算不要改！** 指针包括：数组、struct 和普通整数的指针）

### 关于寄存器
顾名思义， RV64 意味着每一个寄存器大小都从32位扩展到了64位，这意味着你需要在如下操作时注意考虑：
1. 在调用函数前后保存寄存器时，需要在栈上给每个寄存器预留额外的空间，且读写时必须用 `ld`/`sd` 而非 `lw`/`sw`.
2. 上述操作可能导致不同寄存器/变量在栈上的 offset 发生改变，记得做对应调整。

### 关于指针
类似的， RV64 里的指针也默认是 64 位而非 32 位，因此你需要注意以下内容：
1. 当你尝试在栈上 `alloca` 指针时，务必记得他是64位的，且读写时必须用 `ld`/`sd` 而非 `lw`/`sw`.
2. 上述操作也会导致不同变量在栈上的 offset 发生改变，记得做对应调整。
3. 类似的，地址相关计算不能使用 `addw/subw` ，否则会错误的截断地址。
4. 当传参参数无法在 `a0-10` 放下时，记得有些传参的参数也可能是64位的。

在这里再次强调一下，用不用带 `w` 的指令判断标准非常简单：
- 如果一个指令的操作数是整数，那么能换成带 `w` 就换。
- 如果一个指令的操作数是指针/数组头指针/结构体指针，那么一概不使用带 `w` 的指令。
- 如果一个指令没有带 `w` 的版本，那么你不需要对其做任何修改。

### 关于 usize/isize
由于前面不溢出的保证，你可以把它视为32位或64位的任何一个均可。
